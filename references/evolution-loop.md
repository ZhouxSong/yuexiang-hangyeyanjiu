# 终版学习 → 技能自进化闭环（Evolution Loop）

用户（私募股权投资总监）将初版修改为终版后提交，触发本闭环。目标：从用户的修改中学习其研究偏好与写作标准，持续优化技能。**铁律8：未经用户批准，不得写入任何技能更新。**

## 触发条件

- 用户提交终版报告（文件路径或内容），并表达学习意图（如"这是我的终版，学习一下""更新技能"）；
- 或主智能体在阶段5交付初版后，主动提醒用户"您改为终版后提交给我，我将学习差异并建议技能更新"。

## 执行步骤（五步）

### 第1步：Diff（差异识别）
主智能体（或派 `diff-analyst` 子agent，输入初版+终版全文）逐节对比，产出结构化差异清单。每条差异记录：

```
【差异 D-n】
位置：第X章 X.x节（初版第M段 → 终版第K段）
类型：[删减 / 增补 / 改写 / 结构调整 / 口径修正 / 观点修正 / 图表调整]
初版内容摘要：「……」
终版内容摘要：「……」
```

**Diff执行要求**：
- 逐节对比，不遗漏；长报告可派并行子agent分章diff；
- 只记录事实差异，此步不做价值判断；
- 纯格式类差异（标点、空格）归为一组概述，不逐条列。

### 第2步：意图推断（为什么这样改）
对每条差异推断用户意图，标注置信度：

| 修改信号 | 可能的意图/偏好 |
|---|---|
| 删减冗长论述 | 偏好简洁、结论导向 |
| 增补数据/案例 | 重视证据密度、要求具体化 |
| 改写措辞 | 措辞风格偏好（更专业/更克制/更直白） |
| 结构调整（章节合并/拆分/重排） | 章节组织习惯 |
| 口径修正（换数据源/改口径） | 数据口径偏好、信源偏好 |
| 观点修正（改变判断/加强限定词） | 分析立场、风险表述习惯 |
| 增加限定语（"目前""初步""或有"） | 严谨性要求、避免过度断言 |

### 第3步：差异分析报告
产出《初版→终版差异分析报告》交用户：
1. 差异统计（各类型计数）；
2. 逐条差异+意图推断（按章节排列）；
3. 高频模式归纳（跨章节重复出现的同类修改 = 最可能是稳定偏好）。

### 第4步：技能更新建议
从差异中提炼**可泛化、跨场景成立**的规律，形成建议清单。每条建议：

```
【建议 U-n】
来源差异：D-x、D-y（需≥2条同类差异支撑，单条孤例不提炼）
提炼规律：[一句话，如"财务数据一律用经调整口径并注明一次性项目"]
建议写入位置：[SKILL.md哪一节 / 哪个references文件]
建议文本：[拟写入的具体文字]
适用范围：[所有报告 / 仅某类生命周期阶段 / 仅财务章节]
```

**提炼过滤规则（防止过度学习）**：
- 孤例不提炼：单条差异不构成规律，需≥2条同类或跨报告复现；
- 场景特定不泛化：仅适用于该行业的改动只记入该行业备注，不写入通用规则；
- 与铁律冲突的建议直接丢弃（如用户删掉了数据标注，不得建议"取消数据标注"——应改为询问用户意图）；
- 拿不准的列为"待观察"，等下一次终版复现。

### 第5步：用户批准 → 写入技能
1. 建议清单提交用户逐条确认（批准/驳回/修改后批准）；
2. 批准项写入技能对应文件（SKILL.md 或 references）；
3. 在 SKILL.md 末尾追加进化日志：

```
## 进化日志
| 日期 | 触发终版 | 变更摘要 | 批准状态 |
|---|---|---|---|
| 2026-09-05 | XX行业研究终版 | 财务章节统一经调整口径；章节结构调整为…… | 用户批准 |
```

4. 更新完成后向用户汇报写入了什么、写在哪个文件。

## 版本管理提醒

技能自身的版本号升级（如1.1→2.0）不在此闭环内自动进行；累积多次进化更新后若需升版，**必须先询问用户确认新版本号**（用户级规则）。
