# 逐章对抗审查执行规范（Adversarial Review）

对抗审查在阶段3与撰写同步进行：每章完成后立即执行一轮，挑战清单提交用户裁决，**用户未确认前不得改稿**（铁律7）。

## 执行机制

1. **触发时机**：每一章初稿完成（含主智能体自查字数达标）后立即触发，不等全文。
2. **独立子agent**：派一个独立 `general-purpose`（model=reasoning）执行。**不给撰写上下文**——只提供：该章全文、该章对应的生命周期阶段风险清单、本章使用的已核实素材清单。
3. **一轮**：每章仅一轮，不循环追加轮次；用户对裁决结果不满意时可要求对该章重做一轮。

## 挑战对象（严格限三类，不得扩散）

| 类别 | 挑战问题 | 示例 |
|---|---|---|
| **关键数据** | 来源是否权威（对照权威级）？推算/插值是否合理？是否遗漏反方向数据？单位/币种/口径是否一致？ | "图5的2025年24.9亿美元仅有单一来源，未见交叉验证" |
| **逻辑链** | 章内因果/递进是否成立？有无循环论证、以偏概全、时间先后当因果？ | "'因为2025年融资增长，所以商业模式被验证'——融资增长不等于变现能力" |
| **遗漏与盲区** | 反面案例/失败案例/关键竞争者/监管风险是否缺位？对照该阶段风险清单逐条核查 | "成熟期模板要求覆盖'商业化证伪案例'，本章未提及任何失败公司" |

**明确不挑战**：核心结论与观点裁量（归用户）、文风措辞、章节结构编排（归Critic）。

## 挑战清单格式（提交用户裁决）

每章产出一份《章N对抗审查挑战清单》，逐条编号：

```
【挑战 N-1】类别：关键数据
位置：第N章 N.x节 第M段
原文：「……」
质疑：[具体质疑内容]
依据：[支撑质疑的证据或逻辑]
建议处理：[采纳修正 / 补充论证 / 可驳回]
```

末尾附汇总：共X条（关键数据a条、逻辑链b条、遗漏c条），等待用户逐条裁决。

## 裁决与修正流程

1. 用户对每条给出：**采纳** / **驳回** / **部分采纳**；
2. 采纳项由主智能体修正进正文，修正须有据可依（不得借修正引入新数据而不核实）；
3. 裁决记录归档为该章附件，进入交付物清单第4项；
4. 全部裁决完成后方可进入下一章撰写（逐章即时交互节奏）。

## 与阶段4 Critic审查的分工

| | 对抗审查（阶段3） | Critic审查（阶段4） |
|---|---|---|
| 时机 | 逐章、与撰写同步 | 全文组装后 |
| 执行者 | 独立子agent（无撰写上下文） | 主智能体 |
| 对象 | 数据、逻辑链、遗漏（实质性挑战） | 编号连续性、引用对应、口径一致、对抗采纳项落实（形式与一致性） |
| 产出 | 挑战清单→用户裁决 | 自审报告（评分+问题清单） |
